# ZiglinCert

Lean 4 + Mathlib library (toolchain leanprover/lean4:v4.35.0-rc3). It turns interval certificates on 2×2 monodromy
matrices into a kernel-checked group-theoretic conclusion. Written by Claude Opus 5.5 (session "Quantum").

This README replaces the GitHub template text that was here (2026-11-23), after the Bridge's faithfulness read:
TheBridge/fleet/lean_reads/ZiglinCert_faithfulness_2026-11-23.md. That read found the library sound and every cited
theorem faithful. The notes below record its wording points.

## What the kernel checks, and what it does not
- **Checked (`decide +kernel`, then `cert_of_check` → `cert_sound` → `L6_gl2`).**
  - For each exported pair of exact-rational boxes BG and BH, `check BG BH = true`.
  - Hence every G ∈ BG and H ∈ BH is invertible, and for every k ≥ 1 no subgroup of finite relative index in
    ⟨G^k, H^k⟩ ⊂ GL(2, ℂ) is abelian.
- **Not checked by Lean:**
  - that the true monodromy matrices lie in the boxes (CAPD/Arb enclosures plus the export gate: bit-for-bit midrads and
    ball-in-rectangle read-back);
  - the step to the identity component G⁰ of the differential Galois group (monodromy ⊆ Galois, and [G : G⁰] finite);
  - the Morales–Ramis / Ziglin step to non-integrability.

  These are cited, not formalised. So say "box arithmetic and group step kernel-checked", not "Lean-verified
  obstruction".
- **The criteria comments in `ZiglinCert/Boxes.lean`.** The header says each criterion is "⇔" the matrix condition.
  The proved direction is "⇒" (soundness: `crit1_math`, `crit2_math`, `crit1_sound`, `crit2_sound`); the converse is
  not formalised. The comment was left unedited so that the read file keeps its hash.

## Building
- The default `lake build` builds `ZiglinCert` (Certificate and Boxes) but **not the certificates**.
- The certificate check is:
  ```
  lake build ZiglinCert.Certs.All
  ```
  That builds every certificate in `ZiglinCert/Certs/*.lean`, the controls, and the Kerr controls.
- Each certificate file peaks at about 2.8 GB of RSS. Build alone, with LEAN_NUM_THREADS=2 at nice 10.
- Certificate files are generated by `qsim/lean_gen.py` from `lean_export/*.json` and must not be edited.

## Controls, as they actually are (the record is weaker than the prereg)
- `Certs/Controls.lean` (from `qsim/lean_gen_controls.py`):
  - `real_pair_passes`: a real exported pair passes `check`.
  - `poison_comm`: `check G G = false`. The prereg's control 1(b) became this.
  - `poison_seg`: a box widened on every real AND imaginary part fails `crit1`. The generator's docstring said "real
    parts only"; it was corrected on 2026-11-23, and the code always widened both.
- The Kerr controls (`kerrctl_8_v2`, `kerrctl_9_v2`) are proved `check = false`, but they fail through criterion (I),
  so criterion (II) was never exercised in isolation.
- The prereg's control 3 (soundness spot-check) has no artefact.
- **Added 2026-11-23, built at the next compute gap:**
  - `Certs/Controls2.lean`: criterion (II) firing on its own. `crit1 G = true` and `crit2 G G = false`, and a
    non-identical commuting pair G and G·G with crit1 passing for both and crit2 rejecting.

## Non-emptiness (added 2026-11-23, built at the next compute gap)
- `CertConclusion BG BH` is vacuously true for an empty box, and `check` does not test lo ≤ hi.
- Rather than change the cited `check`, `Certs/NonEmpty.lean` (from `qsim/lean_gen_nonempty.py`) proves the following,
  all by `decide +kernel`:
  - lo ≤ hi on every entry of all 128 certificate boxes (64 certificates) and of the Controls boxes;
  - `mne_sound`: non-empty means some matrix lies in the box;
  - `must_fire_empty`: a box with lo > hi is rejected;
  - `must_pass_point`: a point box is accepted.
- Build it with `lake build ZiglinCert.Certs.NonEmpty ZiglinCert.Certs.Controls2`.

## Export flags (labelling)
- `qsim/mr_mn_axis_lattice.py` used to hard-code `certificate_ok=True, gate_bit_for_bit=True` in the 12 `mnlat` exports.
- Since 2026-11-23 it computes `certificate_ok` from the run's own T_L6 result, and sets `gate_bit_for_bit=None`. That
  gate applies only to regenerated exports, and these boxes come from the certifying run itself.
- `qsim/lean_gen.py` accepts None only with that `export_source`.
- The 12 existing JSONs keep their old flags. The certificates themselves are re-decided by the kernel, so nothing
  rested on the flags.
